# osbv2-api

`osbv2-api` (version 0.1.0) is the Python client library for the OSBv2 API. The
distributed top-level package is `osbv2_api`; the `workspaces` subpackage exposes
the workspaces manager endpoints of the Open Source Brain platform and is
imported as `from osbv2_api import workspaces`. The `workspaces` client is
generated by [OpenAPI Generator](https://openapi-generator.tech) from the OSBv2
workspaces API specification (`applications/workspaces/api/openapi.yaml`) and
lives in `osbv2_api/workspaces/`. Clients for other OSBv2 REST API services may
be added later as sibling subpackages (e.g. `osbv2_api.<service>`), which is why
the package is not named after `workspaces`. The library is released under the
MIT license and supports Python >=3.7.

## Install

From this directory:

```bash
pip install .
```

The runtime dependencies are installed automatically:

- `urllib3>=1.25.3`
- `python-dateutil>=2.5.3`

For development an optional extra is available, which adds `pytest>=7.0` and
`pytest-cov>=4.0`:

```bash
pip install ".[dev]"
```

## Usage

The `workspaces` subpackage is imported as `from osbv2_api import workspaces`:

```python
from osbv2_api import workspaces

configuration = workspaces.Configuration(host="https://api.osb.example")

with workspaces.ApiClient(configuration) as api_client:
    pass
```
`workspaces.Configuration` and `workspaces.ApiClient` are re-exported by the
`workspaces` subpackage together with the generated exception types (`OpenApiException`,
`ApiAttributeError`, `ApiTypeError`, `ApiValueError`, `ApiKeyError`,
`ApiException`).

## Testing

Run the test suite from this project root:

```bash
pytest
```

An install is not required: `conftest.py` adds the library root (the directory
containing the `osbv2_api` package) to `sys.path`, and `pyproject.toml` sets
`pythonpath = ["."]` together with `testpaths = ["tests"]`, so the imports
resolve as `osbv2_api.workspaces`. The generated tests live under
`tests/workspaces/`.

## Documentation

Install the documentation dependencies listed in `requirements-docs.txt`
(`sphinx>=7.2`, `sphinx-rtd-theme>=2.0`, `myst-parser>=2.0`, plus the runtime
dependencies `urllib3>=1.25.3` and `python-dateutil>=2.5.3` so autodoc can
import the generated modules), then build the docs:

```bash
uv pip install -r requirements-docs.txt
make -C docs html
```

The result is written to `docs/_build/html/index.html`. It contains both the
Sphinx Python API reference and the generated Markdown REST reference.

## Regenerating the client

The contents of `osbv2_api/workspaces/`, `tests/workspaces/` and
`docs/apidocs/workspaces/` are generated - do not hand-edit them. To regenerate,
run the script from the monorepo root (the directory containing `.git`):

```bash
./regenerate.sh
```

The script requires `openapi-generator-cli` to be installed and overwrites the
generated directories listed above.

## Layout

- `pyproject.toml` - build metadata, dependencies, pytest configuration.
- `setup.cfg` - package metadata (name, version, license, classifiers).
- `README.md` - this document.
- `conftest.py` - puts the library root on `sys.path` so tests run without an install.
- `requirements-docs.txt` - Sphinx/theme/Markdown dependencies for the docs build.
- `osbv2_api/workspaces/` - the generated workspaces client subpackage (imported as `osbv2_api.workspaces`).
- `tests/workspaces/` - the generated test suite.
- `docs/`, built into `docs/_build/html/`.
