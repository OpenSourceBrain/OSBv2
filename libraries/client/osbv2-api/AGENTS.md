# AGENTS.md

`osbv2-api` 0.1.0 — "Python client library for the OSBv2 API." (from `pyproject.toml` `[project]`).

## Layout

- Root files: `README.md`, `pyproject.toml`, `setup.cfg`, `MANIFEST.in`, `LICENSE`, `CHANGELOG.md`, `conftest.py`, `regenerate.sh`, `.gitignore`, plus the generator metadata `.openapi-generator/` and `.openapi-generator-ignore`, which `regenerate.sh` writes at the library root because it passes `-o libraries/client/osbv2-api/`.
- `osbv2_api/` — the distributed package: an empty `__init__.py`, the `workspaces/` subpackage (currently the only one) and `workspaces_README.md`, alongside extra `.openapi-generator/` and `.openapi-generator-ignore` copies — the current `regenerate.sh` writes those two artefacts at the library root (see Gotchas), not here. Further OSBv2 REST service clients are added as sibling subpackages under `osbv2_api/`.
- `tests/` — `tests/test_smoke.py` (hand-maintained smoke test) plus `tests/workspaces/test_*.py` (generated per-model/API test modules).
- `docs/apidocs/` — API docs output directory; generated workspace docs land in `docs/apidocs/workspaces/`.

## Commands

Install:

```bash
pip install .
```

Test (run from the project root):

```bash
pytest
```

Test configuration comes from `[tool.pytest.ini_options]` in `pyproject.toml`: `testpaths = ["tests"]`, `python_files = ["test_*.py"]`, `pythonpath = ["."]`, `addopts = "-ra --import-mode=importlib"`, `minversion = "7.0"`.

Build: **no build command is documented.** The build system is declared as setuptools (`requires = ["setuptools>=61.0", "wheel"]`, `build-backend = "setuptools.build_meta"`), but no build invocation is stated anywhere in the repo.

Lint/format: **none configured and none documented.** There is no ruff/flake8/black/isort/mypy section in `pyproject.toml`, and `setup.cfg` contains only `[metadata]` and `[options] python_requires = >=3.7`. Formatting is not enforced by tooling.

Dev/test dependencies: the optional extra `dev = ["pytest>=7.0", "pytest-cov>=4.0"]` is declared in `pyproject.toml`, but no install command for the extra is documented. No coverage options are configured in `addopts`.

Regenerate the client:

```bash
./regenerate.sh
```

This must be run from the monorepo root (where `.git` exists) and requires the OpenAPI Generator CLI (`openapi-generator-cli`). It invokes `openapi-generator-cli generate -i applications/workspaces/api/openapi.yaml -g python -o libraries/client/osbv2-api/` with `--additional-properties=packageName=osbv2_api.workspaces` (plus `library=urllib3`, `sourceFolder="."`, `packageVersion=1.0.0`, `buildSystem=setuptools`, `generateSourceCodeOnly=true`), so the `-o` target is the library root and the generator emits fully qualified `osbv2_api.workspaces.*` imports itself. It then verifies the output by grepping `osbv2_api/` for top-level `from workspaces.` / `import workspaces` lines and exits non-zero if any were emitted, and finally moves `osbv2_api/workspaces/test` → `tests/workspaces/` and `osbv2_api/workspaces/docs` → `docs/apidocs/workspaces/`.

Docs:

The Sphinx site renders two references: the hand-maintained Python API
reference in `docs/api.rst` (autodoc/autosummary over `osbv2_api`) and the
OpenAPI-generated Markdown REST reference under `docs/apidocs/workspaces/`.
Build both with:

```bash
uv venv .venv-docs --python 3.12
uv pip install --python .venv-docs/bin/python -r requirements-docs.txt
make -C docs html SPHINXBUILD=$PWD/.venv-docs/bin/sphinx-build
```

The HTML output is written to `docs/_build/html/index.html`. `docs/apidocs/workspaces/` is generated by `./regenerate.sh` and must not be hand-edited; `docs/conf.py`, `docs/index.rst`, `docs/api.rst` and `docs/Makefile` are hand-maintained. `docs/_build/`, `docs/generated/` and `.venv-docs/` are gitignored.

## Conventions

- Python 3; `requires-python = ">=3.7"`, with classifiers for 3.11, 3.12 and 3.13.
- MIT license (`LICENSE`, declared via `license-files`).
- Runtime dependencies are limited to `urllib3>=1.25.3` and `python-dateutil>=2.5.3`.
- Tests are files named `test_*.py` under `tests/`; generated ones live under `tests/workspaces/`.
- Packaging is driven by `pyproject.toml` (setuptools), with `[tool.setuptools] include-package-data = true` and `[tool.setuptools.packages.find] where = ["."] include = ["osbv2_api*"]`.
- `setup.cfg` duplicates metadata (name, version, license, classifiers, `python_requires`) in the legacy `[metadata]`/`[options]` form — keep it in sync with `pyproject.toml`.

## Gotchas

- `osbv2_api/workspaces/` is generated by OpenAPI Generator from `applications/workspaces/api/openapi.yaml` (`-g python`, `library=urllib3`, `packageName=osbv2_api.workspaces`, `sourceFolder="."`, `packageVersion=1.0.0`, `buildSystem=setuptools`, `generateSourceCodeOnly=true`). Because `packageName` is the dotted `osbv2_api.workspaces`, the generator emits fully qualified `osbv2_api.workspaces.*` imports natively; `regenerate.sh` rewrites no generated file — it only greps `osbv2_api/` for top-level `from workspaces.` / `import workspaces` lines and aborts with exit 1 if any were emitted, then relocates the tests and docs. Do not hand-edit it — `regenerate.sh` overwrites it.
- `regenerate.sh` is monorepo-relative: it hardcodes `libraries/client/osbv2-api/`, reads `applications/workspaces/api/openapi.yaml`, and moves generated `osbv2_api/workspaces/test` → `tests/workspaces/` and `osbv2_api/workspaces/docs` → `docs/apidocs/workspaces/`. Run it from the repo root containing `.git`, not from this directory.
- With `-o libraries/client/osbv2-api/`, the generator writes its `.openapi-generator/` and `.openapi-generator-ignore` metadata at the library root. Copies also exist inside `osbv2_api/`; they are not written by the current script and could be removed in a separate cleanup.
- Tests do not require an install: the root `conftest.py` adds the library root (the directory containing the `osbv2_api` package) to `sys.path`, and `pyproject.toml` adds `pythonpath = ["."]`, so the import name is `osbv2_api.workspaces`. Run pytest from the project root so this config applies; pytest uses `--import-mode=importlib`.
- `README.md` documents the `osbv2_api` package with the `workspaces` subpackage: install, usage (`from osbv2_api import workspaces`), testing, docs, regeneration and layout.
- `MANIFEST.in` and `.gitignore` exist at the root; their contents are not documented here.
